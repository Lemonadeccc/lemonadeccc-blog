最近我把自己常用的 AI 工具和工作流梳理了一遍。目标不是追求“全家桶”，而是让每个环节都能更快进入可交付状态。

## 一、设计阶段：先把结构说清楚

### 1) 线框草图

- [wiretext](https://wiretext.app/)：快速把页面结构写成线框，适合先定信息层级。
- [mockdown](https://www.mockdown.design/)：用文本表达页面块级布局，适合早期讨论。

### 2) UI 套壳与变体

- [Pencil](https://www.pencil.dev/)：使用 prompt 快速搭建可编辑界面稿。
- [variant ai](https://www.variant.ai/)：先选接近的设计，再用 prompt 调整。导出 `.js` 后，可继续用 CC 或 Codex 做结构和细节修改。

## 二、开发阶段：并行化是核心增益

### 1) 多 Agent + Git Worktree

将每个任务隔离在独立 Git 工作树中，同时运行多个代理，可以明显减少上下文污染和任务互相干扰。  
截至目前，Claude 官方能力已经覆盖了多 worktree 与一部分远程能力，第三方并行工具从“必选”变成了“可选增强”。

### 2) 过去常见方案

- [superset](https://github.com/superset-sh/superset)：第三方并行编排工具。
- [happy](https://github.com/slopus/happy)：第三方开源 CLI 包装器。


1. Claude 官方现在包含多 worktree 工作流。
2. 云端远程运行（`claude --remote` / Claude Code on the web）订阅后都可用。
3. 远程控制本机会话（`claude remote-control`）当前以 Max 为主，Pro 在逐步开放，Team/Enterprise 暂不支持。

因此， Claude 现在生态内逐渐包含例如 `superset` 和 `happy` 的“效率增强器”。

## 三、Skills 生态：把方法论写进执行层

我常用的 skills 资源：

- [skills 官方](https://skills.sh/)
- [superpowers](https://github.com/obra/superpowers)
- [claude-mem](https://github.com/thedotmack/claude-mem/tree/main)
- [react-best-practices](https://github.com/vercel-labs/agent-skills/tree/main/skills/react-best-practices)

其中：

- `superpowers` 更偏流程编排，例如自动 plan、分阶段执行、收尾校验。
- `claude-mem` 侧重上下文压缩与记忆管理，适合长链路任务保持相关性。
- `react-best-practices` 用于在实现阶段约束性能和代码质量。

## 四、当前可复用流程（我的版本）

1. 先做最小可运行功能（MVP），尽快打通关键路径。
2. MVP 基本测试成功后，使用 prompt 约束：健壮性、可维护性、边界处理根据可读性要求做一轮重构。

这套流程对个人项目很实用：前期速度快，中期质量可控，后期维护成本也更低。
