过去一段时间，我把自己在真实项目里使用 AI 的流程重新整理了一遍。  
目标很简单：不是追求工具越多越好，而是让每个环节都更快进入“可交付”状态。

## 一、设计阶段

设计阶段只做两件事：先定结构，再做视觉。

### 1) 线框草图：先对齐信息层级

- [wiretext](https://wiretext.app/)：快速把页面结构写成线框，适合先确认信息层级。
- [mockdown](https://www.mockdown.design/)：用文本表达页面块级布局，适合早期讨论和需求澄清。

### 2) UI 套壳与变体：快速拿到可编辑初稿

- [Pencil](https://www.pencil.dev/)：通过 prompt 生成可编辑界面稿。
- [variant ai](https://www.variant.ai/)：先找接近风格，再用 prompt 调整；导出 `.js` 后继续用 Claude Code 或 Codex 做结构细化。

这一步的关键不是“做漂亮”，而是尽快拿到一个可以迭代的版本。

## 二、开发阶段：并行化 + 隔离，收益最大

### 1) 多 Agent + Git Worktree

当前做法：

1. 一个需求拆成 2-4 个相对独立子任务。
2. 每个子任务绑定独立 worktree 和独立会话。
3. 先合并可验证的小增量，再做跨模块收敛。

这样做可以明显减少上下文污染和互相干扰，协作稳定性会高很多。但复杂任务分多 worktree 会降低效率。

### 2) 生态变化

过去我常用：

- [superset](https://github.com/superset-sh/superset)：并行编排工具。
- [happy](https://github.com/slopus/happy)：CLI 包装器。

现在 Claude 官方已经覆盖了多 worktree 和部分远程能力，这类工具更像增强层，而不是唯一入口。

## 三、CCG Workflow：把多模型协作流程化

`ccg-workflow` 的定位是：Claude Code 负责编排，前端任务优先分给 Gemini，后端任务优先分给 Codex，最后由 Claude 统一审核并落地 patch。

### 1) 安装与前置

```bash
npx ccg-workflow
```

- 需要 `Node.js 20+`。
- 可选安装 `Codex CLI`（偏后端）和 `Gemini CLI`（偏前端）。

### 2) 常用命令

- 全流程：`/ccg:workflow`
- 规划 + 执行分离：`/ccg:plan` + `/ccg:execute`
- 面向任务：`/ccg:frontend`、`/ccg:backend`、`/ccg:debug`、`/ccg:optimize`、`/ccg:review`

先计划再执行：

```bash
/ccg:plan 实现用户认证功能
/ccg:execute .claude/plan/user-auth.md
```

能把会话切换带来的损耗降到最低，换窗口也不容易跑偏。

### 3) ccg 内置功能

- 规范驱动（`/ccg:spec-*`）：
  - 适合约束多、容易偏题的复杂需求。
  - 价值是把“自由发挥”收敛成“按约束执行”。
- 并行实施（`/ccg:team-*`）：
  - 适合可拆成 3 个以上独立模块的任务。
  - 价值是通过 `/clear` + 文件状态传递减少上下文串扰。

### 4) 配置与避坑

- 在 `~/.claude/settings.json` 调整超时参数（如 `CODEX_TIMEOUT`、`BASH_DEFAULT_TIMEOUT_MS`）。
- MCP 工具按复杂度选配：ContextWeaver + Context7 / Playwright / DeepWiki / Exa。

## 四、Skills 可复用流程

常用 skills 资源：

- [skills 官方](https://skills.sh/)
- [superpowers](https://github.com/obra/superpowers)
- [claude-mem](https://github.com/thedotmack/claude-mem/tree/main)
- [react-best-practices](https://github.com/vercel-labs/agent-skills/tree/main/skills/react-best-practices)

对应定位大致是：

- `superpowers`：流程编排（自动计划、阶段执行、收尾校验）。
- `claude-mem`：上下文压缩与记忆管理（适合长链路任务）。
- `react-best-practices`：实现阶段的性能与代码质量约束。

## 五、MCP 

我目前用过 Lighthouse MCP：

- `@danielsogl/lighthouse-mcp`：功能完整，支持 Core Web Vitals、budget 等。

实践里有两个注意点：

1. 跑 Lighthouse 时建议明确要求 LLM “桌面端 + 移动端”都测，很多自动化流程默认只测移动端。
2. 自动化跑分与手动在浏览器 DevTools 中测出来会有差异，建议把趋势和瓶颈定位作为主要参考，不要只盯单次绝对分数。

如果站点托管在 Cloudflare 且遇到爬虫/审计访问问题，可以先检查 `robots.txt` 和缓存策略，必要时清理 `robots.txt` 的相关缓存再重试。

## 六、当前可复用完整流程

1. 先用线框工具明确页面结构和信息层级。
2. 用 UI 生成工具快速拿到首版可编辑稿，避免过早卡在视觉细节。
3. 开发阶段优先做 MVP，按 worktree 并行推进独立子任务。
4. 复杂需求先用 `/ccg:plan` 或 `/ccg:spec-*` 锁定约束，再进入实现。
5. 合并前做统一 review（`/ccg:review` + 人工抽检），最后做稳态重构（健壮性、可维护性、边界处理）。

这套流程的核心先把约束写清楚，再让多模型并行执行，最后由统一审查收口。前期速度快，中期质量稳，后期维护成本可控。
