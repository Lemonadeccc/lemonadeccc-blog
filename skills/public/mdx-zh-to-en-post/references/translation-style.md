# Translation Style (ZH -> EN)

## Goals

1. Keep meaning faithful to source.
2. Keep wording concise and technical where applicable.
3. Keep MDX rendering-safe structure.

## Terminology

1. Prefer stable technical wording over literal phrasing.
2. Keep library and API names unchanged: `React`, `Next.js`, `GSAP`, `Node.js`, `pnpm`.
3. Keep commands and flags unchanged.

## Frontmatter Rules

1. Translate `title`, `type`, `project`, `summary` to natural English.
2. Preserve keys and keep `date` unchanged.
3. Preserve optional `image` path unchanged.

## Markdown / MDX Rules

1. Translate narrative text only.
2. Do not alter code blocks, inline code, links, media paths, or HTML/JSX tag structure.
3. Keep heading hierarchy stable.

## Tone

1. Use direct, practical language.
2. Avoid marketing-style exaggeration.
3. Keep sentence length moderate for technical readability.
